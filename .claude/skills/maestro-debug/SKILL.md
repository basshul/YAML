# 실패 진단

**환경 문제를 먼저 배제한다.** 실측 기준 9회 실패 중 4회가 환경이었고, 코드 결함으로 오진하면
이미 고친 곳을 다시 뒤지게 된다. 아래 순서대로 좁힌다.

## ① 로그 읽기

스위트 로그는 **CRLF + 한글이 콘솔에서 깨진다.** 반드시 `tr -d '\r'`를 거친다.

```bash
cd "<Maestro>/suite_logs" && D=$(ls -dt */ | head -1)
tr -d '\r' < "$D/<이름>.log" | grep -vE "^\s+at |^Caused by" | grep -B10 "FAILED" | head -14
```

- 스택트레이스(`at ...`)는 걷어내야 실제 실패 스텝이 보인다.
- 한글이 깨져도 **id와 영문은 읽힌다** — 그것으로 지점을 특정한다.
- 진행 지점은 `Take screenshot <이름>` 목록으로도 추적된다(어디까지 갔는지 즉시 파악).

## ② 환경 문제인가

| 로그/상태 | 원인 | 대응 |
|---|---|---|
| `device '...' not found` / `UNAVAILABLE` | **USB 연결 끊김** | `adb devices -l` 확인. 비면 사용자에게 알린다(소프트웨어로 복구 불가) |
| 진입부에서 홈·잠금화면 둘 다 못 찾음 | **자동 로그아웃**(유휴 ~10분) | `mResumedActivity`가 `AutoLogoutActivity`/런처인지 확인 → 재로그인 후 **곧바로** 실행 |
| 덤프에는 **직전 화면**이 보이는데 탭이 전부 헛돎 | 같은 자동 로그아웃 — ★**그 창은 접근성 트리에 안 나온다** | 아래 ②-1 |
| `로그인 세션이 만료...` | 하루 경과 | `01_01_Login_Success_old.yaml`. **PIN만으로는 복구 안 된다** |
| 상태가 `killed` | 외부 종료(사용자 중단 등) | 플로우 실패가 아니다. 어디까지 갔는지 로그로 확인 |
| `Unable to launch app` | Server Override의 `APPLY & QUIT` 후 재실행 실패 | 앱 상태 확인 후 재시도 |

환경 문제면 **코드를 고치지 않는다.** 조건을 회복하고 다시 돌린다.

### ②-1 자동 로그아웃 잠금 화면은 **볼 수 없다** (2026-09-15 실측)

유휴 ~10분이면 `autologout.AutoLogoutActivity` 가 뜬다 — **"Enter password to unlock" + 보안
키패드(transkey)** 이고, 요구하는 건 PIN이 아니라 **로그인 비밀번호**다.

★ 이 창은 접근성 트리에 **노출되지 않는다.** `uiautomator dump` 와 Maestro 둘 다 **직전 화면의
트리를 그대로 반환**한다 → "카드 화면이 복원됐다" 식으로 **오진**하고, 그 좌표의 탭·`back` 이
**보안 키패드 위에 떨어진다.** 판정 수단은 하나뿐이다:

```bash
adb shell dumpsys activity activities | grep topResumedActivity   # autologout 이면 트리는 전부 거짓
```

- ⚠️ 입력칸의 `********` 는 **힌트**다. 입력값으로 착각해 "글자가 들어갔다"고 오판하지 말 것.
- **자동화로 풀 수 없다** → `01_01_Login_Success_old.yaml`(`clearState: true`)로 **로그인
  화면부터** 복구한다(그 화면의 transkey 는 트리에 정상 노출된다). PIN 은 계정(서버) 상태라 유효하다.
  `clearState` 는 앱 언어를 한국어로 되돌리므로, en 검증 중이면 `_set_lang_en_old.yaml` 을 다시 돌린다.
- `run_test.ps1` 이 실행 전에 이걸 보고 **exit 3 으로 끊는다**(2026-09-15 신설).
  `clearState` 플로우는 예외 — 안 그러면 복구 수단 자체가 막힌다.
- **실행 사이에 공백을 두지 말 것.** 진단·편집하는 몇 분 사이에 걸린다(하루에 2회 실측).

## ③ 실패 시점 화면을 본다

로그만으로 부족하면 실기기 화면을 덤프한다(실행이 끝난 뒤에만).

```bash
adb shell uiautomator dump //sdcard/d.xml
adb pull //sdcard/d.xml <scratchpad>/d.xml
tr '<' '\n<' < <scratchpad>/d.xml | grep -oE '(resource-id="[^"]*"|text="[^"]*")' | grep -v '=""'
```

`takeScreenshot`으로 찍힌 png는 Maestro 루트에 남는다 — 이미지로 직접 확인하는 게 가장 빠를 때가 많다.

## ④ 코드 결함 유형

환경이 아니라면 아래 넷 중 하나다. 전부 **"그 시점 데이터/문구가 그랬을 뿐"인 가정**에서 나온다.

### 문구 전체매칭 (가장 흔하고 가장 늦게 터진다)
Maestro 텍스트는 **전체 매칭**이다. 부분 문구를 쓰면 **에러 없이 조용히 SKIP**된다.
조건부 블록 안이면 실패조차 하지 않아 거짓 통과가 된다.

| 쓰던 값 | 실제 문구 |
|---|---|
| `"나중에 하기"` | **"다음에 하기"**(`btnCancel`) |
| `"간편 비밀번호"` | "간편 비밀번호를 입력하세요" |
| `"잔액"` | "잔액이 부족합니다" |
| `"국내송금"` / `"예약"` | "국내 송금"(공백) / "예약하기" |

→ **id로 판정한다.** 잠금화면 `input_dot_1`, 홈 `bottom_item_home`.
→ 문구가 꼭 필요하면 실기기 덤프로 원문을 확인하고 `.*`/`[\s\S]*`를 쓴다.

### 데이터 의존
목록 내용·개수·구성은 실행 시점마다 다르다. **개수와 순서를 가정하지 말 것.**

- 목록 첫 행 이름이 **한글**이면 `inputText`가 거부한다(ASCII만 입력 가능)
  → 셀렉터에 `id` + `text: "[A-Za-z]{3}[A-Za-z ]*"` 를 함께 줘 영문 행을 직접 집는다.
- 사용 내역 카테고리는 **지출 있는 것만** 표시된다(데이터 없으면 반대로 전체 목록이 뜬다).
- 차트는 **이번 달 지출이 0이면 아예 없다**(`data_not_found`). 월 경계에서 터진다.
→ 조건부로 감싸되 **"최소 1개는 존재"를 단언**해 거짓 통과를 막는다.

### 타이밍
서버 조회는 느리다. **즉시 `assertVisible`을 쓰지 않는다.**
Wallet 거래내역은 로딩이 최대 2분까지 간다(40초로는 부족했다) → `extendedWaitUntil` + 넉넉한 timeout.

### 화면 밖 요소 / 겹침
접근성 트리에 bounds가 남아 있어도 **실제로는 화면 밖**일 수 있다. 그 좌표에 다른 요소가 그려져 있으면
탭이 `COMPLETED`로 찍히고도 엉뚱한 동작이 일어난다(송금 2단계에서 약관 브라우저가 열린 사례).
→ **스크롤로 겹침을 해소한 뒤** 탭한다. 높이 0 노드 탭 함정과 같은 부류다.
→ 다이얼로그·바텀시트가 뜨면 **뒤 화면이 트리에서 사라진다** → 팝업을 먼저 닫는다.

## ⑤ 고친 뒤

- **수정이 파일에 남았는지 확인한다.** 적용·확인·PASS까지 받은 수정이 사라진 사고가 있었다.
  실행 직전 `Select-String` 카운트를 찍는다(`maestro-run` 참고).
- **임시본을 쓰고 있었다면 반드시 재추출한다.** 본 파일만 고치고 임시본을 그대로 돌려
  한 세대 전 버전을 검증하고 통과로 착각한 사고가 있었다.
- 조건부 처리만 추가하고 끝내지 말 것 — **결과 도달을 강제하고 단언**해야 거짓 통과가 안 된다.
