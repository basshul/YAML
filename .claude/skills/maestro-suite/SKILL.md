# 구 UI 회귀 스위트

실행기는 `Maestro\run_suite.ps1`(2026-09-02 재작성). 개별 플로우 실행 규약은 `maestro-run` 스킬 참고.

**현재 39항목 / 예상 약 5시간 19분** (기본 G1~G4. G9는 제외).

⚠️ **2026-09-11: `21_Card` est 8분 → 30분.** 종전 값은 **신청 블록이 조용히 SKIP되던 실행**을 잰
것이었다([01]의 가드가 전체매칭으로 안 맞아 [01]~[10]이 통째로 건너뛰어졌다). 이제 그 구간이
실제로 돌아 **실제 카드 신청이 접수되고 [10]이 취소해 원복**한다 — 중간에 끊기면 신청이 남는다.
같은 날 `push=$true`(= [24] Global QR 픽스처 의존)와 `needs.balance=3000`(= [33-1] CU 3,000원
실구매 후 취소, 잔액 부족 시 **실계좌 자동충전**)도 빠져 있던 것을 채웠다.

⚠️ **`est` 는 손으로 적은 값을 믿지 말 것** (2026-09-11 전수 대조). `suite_logs\*\SUMMARY.md` 의
PASS 행 소요를 모아 `ceil(실측 최대 × 1.1)` 로 21항목을 고쳤다 — `11_IntlTopup` 4→11분,
`25_Profile` 6→12분, `20_Booking` 5→10분, `02_02` 12→16분처럼 **절반 이하로 적혀 있던 것**이 있었고
`06_Registration` 28→20분처럼 부풀려진 것도 있었다. **완주 PASS 기록이 없는 11항목**
(`08_MyQR`·`10_DomesticTopup`·`03_Domestic`·`16_ATMWithdraw`·`02_01`·`21_Card`·G4 3개·G9 2개)은
손으로 적은 값 그대로다 → 돌려서 PASS가 남으면 같은 방식으로 갱신한다.

## `maestro test Old\` 로 폴더를 통째 돌리면 안 된다

1. **순서가 곧 상태 의존성이다.** 로그인 상태가 앞뒤로 이어지고, `clearState` 플로우가 로그아웃시키면 그 뒤에 재로그인을 끼워야 한다.
2. **딸려 들어간다.** `_*.yaml` 헬퍼와 appId가 다른 stag 전용 파일까지 실행 대상이 된다.
3. **계정을 소모하거나 실결제가 나가는 플로우**를 기본에서 빼야 한다.

## 실행

```powershell
$PSNativeCommandArgumentPassing = 'Legacy'
.\run_suite.ps1 -List                      # 실행 계획 + 예상 소요만 출력
.\run_suite.ps1                            # 기본 = G1,G2,G3,G4 (G9 파괴적 제외)
.\run_suite.ps1 -Group G2                  # 그룹만
.\run_suite.ps1 -From 09_Home              # 해당 항목부터
.\run_suite.ps1 -Only 14_                  # 이름 부분일치
.\run_suite.ps1 -Names 08_MyQR,03_Domestic # 적은 순서 그대로 (그룹 무시)
.\run_suite.ps1 -Resume                    # 마지막 실행에서 못 끝낸 그룹부터
.\run_suite.ps1 -Balance 12000             # 잔액을 사람이 알려준다
.\run_suite.ps1 -Build live                # 운영. 요청이 있을 때만
```

전체 파라미터: `-Lang -Group -From -Only -Names -Balance -Resume -StopOnFail -NoRecover -SkipLint -List -Device -Build -AutoCharge -MaxCharge -AppId`

- ⚠️ **옵션을 확인할 때는 반드시 `-List`를 붙인다.** 빼면 실기기에서 진짜로 돈다.
- 결과는 `suite_logs\<타임스탬프>\`에 항목별 `.log` + `SUMMARY.md`.
- **동시에 두 개를 돌리지 말 것.** 기기가 하나라 충돌한다.
- PowerShell 인자 전달은 **해시테이블 스플래팅**으로. 배열 스플래팅은 `-AppId` 같은 명명 파라미터에 바인딩되지 않는다(`$args`는 자동 변수라 이름으로 쓸 수 없다).

## 확정된 결정 4건

① **범위 = 전부 포함**(실결제·계정소모까지). 단 **G9는 기본에서 뺀다.**
② **실패 시 = 계속 + 자동 복구**(`_suite_recover_old.yaml`). ⚠️ **복구가 2회 연속 실패하면 중단**한다 — 안 그러면 남은 항목이 전부 FAIL로 찍히고 몇 시간이 날아간다. `-NoRecover`로 끌 수 있다.
③ **잔액 = 부족하면 SKIP + 리포트에 사유 명시**(코드 결함 FAIL과 갈라 보이게).
④ **준비 상태는 검사하지 않는다.** 회원가입을 해보기 전에는 계정 존재를 알 수 없다. 준비가 안 된 실행은 휴먼 에러로 본다 → `test006/test007` 존재·픽스처 게이트를 넣지 않는다. 사람용 체크리스트는 `ENVIRONMENT.md`.

## 실행 전 게이트 (스크립트가 자동으로 본다)

1. **린터** — `lint_flows.ps1`을 돌려 **ERROR가 있으면 중단**한다(`-SkipLint`로 무시 가능).
2. **빌드 설치 확인** — 기기에 해당 패키지가 없으면 전 항목이 `launchApp`에서 죽으므로 즉시 종료.
3. **해상도 변경 경고** — 지난 실행과 다르면 경고한다. ⚠️ **실패가 무더기로 나면 셀렉터 버그로 단정하지 말 것** — 해상도 문제일 수 있다(고치는 법은 `maestro-yaml` 스킬).
4. **기기 재연결 대기** — `Wait-Device`가 최대 3분 기다린다(USB가 자주 끊긴다).

## 서버가 LIVETEST인지 — 3중으로 본다

stag는 Server Override 기본값이 **STAG**이고 **`clearState`가 그 선택을 되돌린다.** 한 곳이라도 강제가 빠지면 전 스위트가 **조용히 gmeuat로 돈다**(2026-08-27 사고: gmeuat 1,113건 / livetest 0건).

1. P0에서 빌드 설치 확인 → 2. **첫 항목 직후 조기 검사**(gmeuat가 잡히면 즉시 중단) → 3. 종료 시 전체 집계.

3시간 돌고 나서야 엉뚱한 서버였다는 걸 아는 게 최악이라 조기 검사를 넣었다.

- ⚠️ **콜드스타트 gmeuat은 유출이 아니다**(2026-09-09 실측). `clearState` 직후 앱이 설정 API `ChangePasswordRule` 하나를 gmeuat로 호출한다 → **그 엔드포인트만 콜드스타트로 분류**하고 나머지 gmeuat는 전부 위반으로 본다.
- 강제 누락 자체는 린터 **`E08`**이 정적으로 잡는다.

## 잔액

- ⚠️ **자동으로 읽지 못한다** — 구 UI 홈은 잔액을 `XXX,XXX`로 마스킹한다. 그래서 `-Balance <원>`으로 **사람이 넘긴다.** 생략하면 게이트 없이 그냥 돌고 리포트에 "잔액 미확인"으로 남는다.
- ⛔ **자동 충전은 기본 꺼짐**(2026-09-03). KFTC 계좌에서 자금을 끌어오려면 **OTP/생체인증**이 필요해 자동화로는 입금이 완주되지 않는다. `_suite_charge_old.yaml`은 만들어 뒀지만 **완주 확인 전**이라 `-AutoCharge`로 명시할 때만 쓴다. **잔액은 사람이 미리 채우는 게 정석이다.**
- ⚠️ 잔액은 **계산 단계에서 검증된다.** 부족하면 "거래를 진행하기 위한 잔액이 부족합니다" 시트가 뜨는데, 그 시트에는 **`자동이체 계좌 선택`이 함께 뜨고 확인을 누르면 실계좌 자동충전이 발생**한다 → 자동으로 누르지 말 것.
- 임계값을 **고정값으로 박지 말 것.** 해외송금 최소 금액은 환율 연동이라 매일 바뀐다. 금액은 flow-level `env`로 넘기고, 낡으면 앱의 `limitErrorMsg`가 잡아낸다.

## 실행 환경 전제

- **USB 연결이 자주 끊긴다**(9/3 하루 2회, 8/31~9/1 4회). `Wait-Device`가 버티지만 **케이블·포트 점검이 근본 해결**이다.
- 유휴 ~10분이면 앱이 **자동 로그아웃**된다.
- ⚠️ **수동 테스트로 앱 지문 인증이 켜지면 전 스위트가 진입 자체를 못 한다**(증상은 진입 10스텝쯤 사망 + 자동 복구도 실패). 설정에서 OFF를 먼저 확인할 것.
- ⚠️ 백그라운드 장기 실행이 **PC 메모리 부족으로 강제종료**된 적이 있다(3회). 여유 3GB를 확보하고 시작한다.
- 진단은 `maestro-debug` 스킬의 환경 진단표.

⚠️ **실패 분류기 주의** — 로그 첫 줄의 `--env` 에코를 매칭해 **전 FAIL을 "세션 만료(환경)"로 오분류**하던 버그가 있었다(수정됨). 분류를 손볼 때 같은 함정을 다시 만들지 말 것.
