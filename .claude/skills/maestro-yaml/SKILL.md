# 플로우 yaml 작성

대상은 **구 UI(`HomeActivityV2`)** 용 `Old\*_old.yaml`이다.
개편 UI판을 그대로 가져오면 진입 경로부터 깨진다.

## 파일 구조

```yaml
appId: ${APP_ID}
env:                      # 반복 값은 flow-level env로 변수화
  SENDNOW_AMOUNT: "14000"
---
# 공통 진입: launchApp → Server Override → PIN → 홈
# [01] [High] <화면> - <검증 내용>
- tapOn: { id: "..." }
```

- 케이스 헤더는 `# [NN] [Low|Medium|High] <설명>` 규약이고 ClickUp 케이스와 1:1 대응한다.
- `_` 접두사는 **헬퍼**다(`runFlow: "_server_override_old.yaml"` 등). 즉석 블록을 만들지 말고 헬퍼를 쓴다.
- **로그에는 치환 전 원문이 찍힌다** → 변수 치환 여부는 화면 동작으로 확인한다.

## 구 UI 전환 규칙

| 대상 | 개편 UI | 구 UI |
|---|---|---|
| 홈 도달 판정 | `text: "Home"` | **`id: bottom_item_home`** |
| 설정 진입 | 프로필 탭 | **드로어 `iv_nav` → "설정"** |
| 로그아웃 | 프로필 탭 | **드로어에만 있다** |
| 입력 필드 | 퍼센트 좌표 | **컨테이너 id** |

- ⚠️ **PIN(간편 비밀번호) 화면은 두 UI가 같다 → 전환 대상이 아니다**(그래서 위 표에 없다).
  구 UI에도 `"4자리 숫자를 입력하세요"`·`input_dot_1`~`4`·`keypadContainer`가 그대로 있다(2026-09-01 실측).
  id를 권장하는 건 전환 때문이 아니라 언어·문구 변경에 안 흔들려서다.
  ⛔ 이걸 "문구는 V3 전용"으로 오독해 `Old\`에서 76곳을 걷어냈다가 되돌린 사고가 있었다.
- 홈 복귀 판정에 `btnTransfer`를 쓰지 말 것 — 구 UI 홈은 스크롤 위치를 유지해 상단 카드가 화면 밖일 수 있다.
- `back` 1탭이 액티비티를 벗어난다고 가정하지 말 것 → `repeat: { while: notVisible <다음 화면 id> }`.
  `repeat`는 `while` + `commands`(필요시 `times` 병용) 형태만 쓴다. **`maxRuns`는 없는 키다.**

## 셀렉터 함정

- **텍스트는 전체 매칭**이다. 부분 문구는 **에러 없이 조용히 SKIP**된다 → 되도록 `id`로 판정한다.
  개행이 섞이면 `.*`로 부족하다 → **`[\s\S]*`**(단일인용).
- **id에 패키지명을 박지 말 것.** `com.….livetest:id/xxx`는 stag에서 매칭되지 않는데
  조건부 블록 안이면 에러 없이 SKIP된다. Maestro는 짧은 id를 부분 매칭하므로 `id: "balloonClose"`로 쓴다.
- **id는 정규식**이라 `"btnTwo|btnClose"`처럼 여러 후보를 함께 받을 수 있다.
- `text:`와 `id:`를 **함께 지정**하면 조건을 좁힐 수 있다(예: 영문 이름 행만 집기).
- `rightOf`/`below` 상대 셀렉터는 스와이프 액션 아이콘에서 불안정 → index 기반으로.
- `inputText`는 **한글을 입력하지 못한다** → 검색어는 ASCII를 쓰고, 런타임에 읽은 값이면 ASCII 행을 골라 쓴다.
- PIN 키패드는 셔플되지만 **화면 진입 시에만이고 탭마다가 아니다**(2026-09-01 실측 정정).
  대기 없는 연타 3회가 3/3 정확히 입력됐다 → **탭 사이 대기는 불필요.**
  위험한 건 **첫 탭 전**이다 — 화면 도달을 안 기다리고 누르면 같은 글자를 가진 다른 요소를 집는다
  (실례: 금액에 `"2"` 입력 직후 대기 없이 `tapOn: "2"`로 PIN 시작).
  → **숫자 탭 앞에 `id: input_dot_1`(또는 `keypadContainer`) 도달 대기.**
- 접근성 트리에 안 잡히는 WebView 텍스트가 있다 → 그 경우만 좌표로 우회.
- **범용 `tapOn: "닫기"` 금지** — 엉뚱한 X를 눌러 앱이 런처로 빠져나간 사고가 있다.

## 기기·해상도가 바뀌어도 버티게 쓰기

2026-09-09 테스트 기기 교체(1080x2220 → SM-S911N 1080x2340)에서 **7개 파일이 한꺼번에 깨졌다.**
증상은 제각각이었지만 원인은 하나다 — **요소가 화면 밖으로 밀리거나 키패드에 가려진다.**
아래 셋은 `lint_flows.ps1`이 정적으로 잡는다: `W11_COORD_NO_ASSERT` / `W12_HIDEKEYBOARD_AS_BACK` /
`W13_INDEX_AFTER_SCROLL`.

- **`index:`는 행 앵커가 아니라 "그 순간 화면에서 가장 위"다.**
  `Filters.INDEX_COMPARATOR = compareBy({bounds.y},{bounds.x})` 이고 **명령마다 다시 계산된다.**
  한 화면에 보이는 행 수가 달라지면 같은 index가 **다른 행**을 가리킨다
  (2026-09-08 `13_06`이 이 이유로 타겟이 아닌 송금인을 지웠다).
  → **이름으로 앵커한다**: `childOf: { containsDescendants: ["<이름>"] }`
    ⚠️ 카드 **안에 있는** 요소에만 성립한다 — `moreIcon`은 되고 `delete`는 안 된다(형제 배경 레이어).
  → 앵커가 불가능하면 `scrollUntilVisible ... centerElement: true`로 **위치를 고정한 뒤** index를 쓴다.
- **고정 퍼센트 `swipe`로 목록을 옮기지 말 것.** 같은 30%가 해상도마다 다른 행 수만큼 움직인다.
  `scrollUntilVisible`(+`centerElement: true`)은 기기와 무관하다.
- **좌표 탭은 최후 수단이고, 쓰면 반드시 결과를 단언한다.** 좌표는 빗나가도 **에러가 없다** → 거짓 통과.
  "텍스트가 두 줄이라 매칭이 안 된다"는 대개 **전체 매칭 때문**이다 →
  `'라벨[\s\S]*'`로 받으면 좌표가 아예 필요 없다(`21_Card [19]`가 그 예였다).
- **`hideKeyboard`는 키보드가 없으면 뒤로가기로 동작한다.** 입력 직후에만 두거나 `when:`으로 가드한다.
  `26_Menu`에서 앱이 홈으로 튀고 탐색본이 가입 폼을 벗어난 원인이 이것이었다.
- **키패드가 하단 요소를 덮으면 접근성 트리에서 사라진다** — "필드가 없다"가 아니라 "가려졌다"이다.
  실측 2건: 인도네시아 송금인 폼의 Address·City / `14_01`의 금액 퀵칩("10,000 KRW").
  → 입력 직후 `hideKeyboard` 한 줄이면 풀린다.
  ⚠️ **계정·데이터 차이로 오진하지 말 것** — 실제로 "계정마다 필드 수가 다르다"고 결론 내고
    조건부 분기를 넣었다가 되돌렸다. 폼은 두 기기 모두 5필드였다(계층 덤프로 확인).
- **단언은 화면에 보이는 순서대로 놓는다.** 아래로 스크롤한 뒤에는 위쪽 필드를 다시 찾을 수 없다.
- **화면 밖일 수 있는 요소는 탭 전에 `scrollUntilVisible`.** 홈 복귀 판정은 `bottom_item_home`
  (구 UI 홈은 스크롤 위치를 유지해 상단 카드가 화면 밖일 수 있다).
  요소 **유무 자체**가 상태에 따라 갈리면(계좌 5개일 때 사라지는 `accAddImageView`) 조건부로 감싼다.
- **자기교정 루프**를 쓴다. 닫힌 행의 `delete` 탭이 카드에 먹히는 것처럼 한 번에 안 되는 조작은
  `repeat`로 "아직 목표 상태가 아니면 다시" 하게 두면 기기가 바뀌어도 스스로 맞춘다.

## 거짓 통과를 막는 구조

**조건부 처리만 있고 assert가 없으면 거짓 통과다.** 성공·실패를 둘 다 `runFlow: when:`으로만 두면
아무것도 안 떠도 EXIT=0이 된다. 순서는 항상 이렇게 간다.

```yaml
# 1) 결과 도달을 먼저 강제한다 (성공/실패 문구를 모두 넣는다)
- extendedWaitUntil:
    visible:
      text: ".*(성공|완료|잔액|실패|오류).*"
    timeout: 120000
# 2) 실패 경로를 명시적으로 배제한다
- assertNotVisible:
    text: ".*잔액이 부족.*"
# 3) 성립을 단언한다
- assertVisible:
    text: ".*(성공|완료).*"
```

- 데이터 유무로 갈리는 요소는 **조건부로 감싸되 "최소 1개 존재"를 단언**한다.
- 탭 뒤에는 **결과 assert**를 붙인다(높이 0 노드·화면 밖 요소는 탭이 성공으로 찍힌다).
- 실패시켜야 할 것을 닫고 진행하지 말 것 — 세션 만료·잔액 부족은 **즉시 실패**가 정답이고,
  그 판정은 **홈 대기보다 앞**에 둔다(뒤에 두면 타임아웃이 먼저 나서 원인이 가려진다).

## 편집 규칙

- yaml은 **UTF-8(BOM 없음)**, 개행은 파일마다 다르다(CRLF/LF) → **읽은 그대로 보존**한다.
- **PowerShell `Get-Content`/`Set-Content`로 편집하지 말 것** — 한글이 깨진다.
  Edit/Write 도구나 Python(`io.open(..., newline="")`)을 쓴다.
- YAML **이중인용 안에서는 백슬래시를 2겹**으로(1겹이면 `Parsing Failed`로 파일이 통째로 죽는다).
  `\s`가 필요하면 단일인용(`'GMEPay[\s\S]*입금'`).
- 수정 후 **파싱 검증**을 습관화한다: `python -c "import yaml,io; print(len(list(yaml.safe_load_all(io.open(P,encoding='utf-8')))[1]))"`

## 대형 파일 작업 방식

1000줄+ 파일은 **처음부터 섹션 분리 → 개별 검증 → 전체 1회 확인** 순서로 간다.
통짜로 반복 실행하면 한 번에 반나절이 날아간다(통짜 13회 → 분리 2회로 끝난 실증이 있다).

- Maestro에는 케이스 선택 옵션이 없다. **한 파일이 곧 한 실행 단위**다.
- 부분 검증은 본 파일에서 필요한 구간을 잘라 `Old\_tmp_*.yaml`로 추출해 돌린다.
- ⚠️ **수정은 항상 본 파일에 하고 임시본은 재추출한다.** 본 파일만 고치고 임시본을 그대로 돌려
  **한 세대 전 버전을 검증하고 통과로 착각한 사고**가 있었다.
- 검증이 끝나면 임시본은 정리한다.

## 실행이 실계좌에 닿는다

- 실기기 + 실서비스라 **실제 결제·충전·송금이 발생**한다. 잔액 부족 시 자동충전이 걸리는 화면이 있다
  (송금 잔액부족 시트의 `자동이체 계좌 선택`, GME Shop "구매하기").
- 로그인 실패 5회 제한, PIN 오입력은 계정 잠금 → **추측 금지**.
- ⛔ 자격정보(비밀번호·PIN)를 저장소 문서에 적지 않는다. 실제 값은 메모리에만 둔다.
- `clearState: true`가 걸린 플로우는 실행하면 **로그아웃된다** → 이후 재로그인이 필요하다.
