## 왜 스위트가 따로 있는가

`maestro test Old\` 로 폴더를 통째 돌리면 안 되는 이유 셋. 이것만 여기 남긴다.

1. **순서가 보장되지 않는다.** 이 스위트는 로그인 상태가 앞뒤로 이어진다 —
   `clearState` 플로우가 로그아웃시키면 그 뒤에 재로그인을 끼워야 한다.
2. **딸려 들어간다.** `_*.yaml` 헬퍼와 appId가 다른 `stag`/`sgt` 파일까지 실행 대상이 된다.
3. **계정을 소모하거나 실결제가 나가는 플로우**를 기본에서 빼야 한다.

## 빠른 참조

```powershell
$PSNativeCommandArgumentPassing = 'Legacy'   # 생략 시 env 값의 `|`가 cmd 파이프로 해석돼 즉사
.\run_suite.ps1 -List                        # 실행 계획만 출력
.\run_suite.ps1                              # 기본 = G1,G2,G3,G4,G5 (G9 파괴적 제외)
.\run_suite.ps1 -Names 08_마이QR_수신과송금,03_국내송금_월렛과계좌   # 적은 순서 그대로
```

- **동시에 두 개를 돌리지 말 것.** 기기가 하나라 Maestro 실행이 충돌한다.
- 🧹 **G5(`90_정리_데이터원복`)는 테스트가 아니다.** 앞선 항목이 남긴 데이터를 지우는 전용 플로우로,
  검증을 하나도 하지 않는다. 그래서 **여기가 FAIL 이어도 테스트 결과는 유효하고**, 반대로
  **PASS 가 "원복했다"는 뜻은 아니다**(원복할 게 없으면 그냥 통과한다) → 로그를 볼 것.
  ⛔ **스위트가 중간에 끊겨 G5 를 못 돌면 `20_예약`이 결제한 KTX 표가 남는다.** 그때는 단독 실행:
  `.\run_test.ps1 -lang ko -flow "Old\90_정리_데이터원복_old.yaml" -User <이름>`
  ⛔ 자격정보 원복(`04_03` PIN · `04_04` 로그인 비번 · `21_카드` 카드 PIN)은 **G5 로 옮기지 않는다** —
  미루면 뒤 항목이 전부 로그인에 실패하고 5회 제한으로 계정이 잠긴다.
- ⚠️ **옵션을 확인할 때는 반드시 `-List`를 붙인다.** 빼면 실기기에서 진짜로 돈다.
- ⚠️ **기본 세트에 들어 있다고 "부작용 없음"이 아니다.** `11_해외충전_통신사상품결제`·`12_청구서결제_해외빌러`는
  **실제 결제가 나가고 취소가 안 된다**(계획 출력에 `🔴비가역`으로 표시된다).
  각 항목의 `note`를 반드시 확인할 것.

## ⛔ 선택 규칙 — 일부만 고르면 조용히 깨지는 조합

스위트 표의 **순서가 곧 상태 의존성**이다. 그런데 `-Names` 나 화면의 중요도 필터로
일부만 고르면 사슬에서 **중간 고리만 빠진다.** 빠진 고리가 "되돌리는 항목"이면
실행은 끝까지 가고 초록불도 뜨는데, 남의 계정에 비밀번호가 걸려 있거나 데이터가 쌓인다.

그래서 **자동으로 끼워 넣는다.** 규칙은 표의 `autoAdd` 필드가 정본이고,
`-List` 와 web-runner 확인 창에 이유와 함께 찍힌다.

| 규칙 | 끼우는 것 | 조건 | 안 끼우면 |
|---|---|---|---|
| `G3_ACCT_RESTORE` | `14_03_입금_GMEPay가상계좌` | G3 중 하나 **＋** G4 중 하나를 골랐을 때 | G4 가 **test123 그대로** 돌아 남의 계정 PIN·로그인 비밀번호를 바꾼다 |
| `SENDER_PURGE` | `13_06_해외송금받기_송금인일괄삭제` | `13_01`·`13_02`·`13_03` 중 하나라도 골랐을 때 | 송금인 잔재가 쌓여 다음 실행의 등록·행 선택이 어긋난다 |

둘 다 **High 가 하나도 없어** 중요도 High 필터에 통째로 빠지는데,
짝이 되는 항목(`04_03`·`04_04`·`13_01`~`13_03`)은 High 라 남는다 — 그래서 생긴 구멍이다.
실측(2026-10-30): High 필터 29개/198분 → 규칙 적용 후 **31개/3시간 28분**.

### 규칙을 더할 때

```powershell
@{ n="..."; g="..."; ...
   autoAdd=@{ id="규칙이름"
              when=@("이 중 하나라도 골랐고")
              with=@("이 중 하나라도 함께 골랐을 때")   # 생략하면 조건 없음
              why="안 끼우면 무엇이 어떻게 틀어지는지" } }
```

- `autoAdd` 는 **되돌리는 쪽**(원복·정리)에만 단다. 검증하는 항목에 달지 말 것 —
  그건 사용자가 고를 몫이다. 규칙은 "고르지 않으면 틀어지는 것"만 담는다.
- 넣는 자리는 **표 순서**가 정한다(표 순서 = 의존 순서). `-Names` 의 순서는 그대로 둔다.
- ⛔ 적용 코드에서 `$names` 라는 변수명을 쓰지 말 것 — PowerShell 변수는 대소문자를
  구분하지 않아 **파라미터 `$Names` 를 덮어쓴다**(2026-10-30 실측: 헤더가 `(-Names 지정 순서)` 로 바뀌었다).
- web-runner 의 `withAutoAdded()` 는 **확인 창 미리보기용 사본**이다. 실제 적용은
  `run_suite.ps1` 이 다시 하므로 사본이 틀려도 실행은 맞다 — 다만 확인 창이 거짓말을 한다.

## ⏭ 게이트 — 건너뛰어도 되는 블록 표시

중요도 High 만 돌릴 때, **High 가 하나도 없는 파일은 통째로 빠진다**(파일 단위 필터).
그런데 **도는 파일 안의 非High 케이스**는 그대로 돌았다. 게이트는 그중 일부를 건너뛴다.

```powershell
.\run_suite.ps1 -SkipOptional ...                                      # 스위트
.\run_test.ps1 -lang ko -flow "Old\..." -ExtraEnv SKIP_OPTIONAL=true   # 단독
```

### ⛔ 자동으로 고를 수 없다 — 사람이 표시한다

"非High 니까 건너뛴다"는 규칙은 **플로우를 깨뜨린다.** 非High 케이스가
뒤의 High 케이스의 **전제**인 일이 흔하기 때문이다. 실제 사례:

| 파일 | 모양 | 게이트 가능? |
|---|---|---|
| `11_해외충전` | [01]→[02]→…→[09] 가 **한 줄로 이어진 단계** | ❌ 중간을 빼면 [09] 에 도달 못 한다 |
| `21_카드` [11] Medium | 화면에서 CVC 를 읽어 `output.cvc1~3` 에 둔다 | ❌ [12] High 가 그 값으로 인증한다 |
| `21_카드` [20] Medium | 분실신고 진입 → 취소 → back | ✅ 제자리로 돌아온다 |

→ 기준은 중요도가 아니라 **왕복인가**다. 세 가지를 모두 만족해야 달 수 있다:

1. 블록이 끝나면 **시작했던 화면으로 돌아온다**(back·탭 재진입 포함).
2. 블록이 **`output.*` 를 만들지 않는다** — 뒤에서 쓰면 거기서 죽는다.
3. 블록이 **앱 상태를 바꾸지 않는다**(설정 변경·데이터 생성은 제외).

### 다는 법

```yaml
# ⏭ [게이트] [20] 전체 — 분실신고 → 취소 → back 왕복.
#   `-ExtraEnv SKIP_OPTIONAL=true` 로 넘기면 건너뛴다. 미지정(기본)은 실행한다.
- runFlow:
    when:
      true: ${typeof SKIP_OPTIONAL === 'undefined' || SKIP_OPTIONAL !== 'true'}
    commands:
      - ...
```

⚠️ **플로우 머리말 `env:` 에 기본값을 두지 말 것** — 머리말 기본값이 `--env` 를
덮어써서 게이트가 영영 안 먹는다. `typeof ... === 'undefined'` 로 미지정을 받아낸다.

⚠️ **이 숫자를 정밀하게 읽지 말 것.** 게이트 없는 두 실측이 서로 **11스텝** 차이난다 —
조건부 블록(팝업 등)이 떴다 말았다 하는 잡음이고, 측정하려는 효과(19스텝)와 자릿수가 같다.
확실한 증거는 시간이 아니라 **로그의 `SKIPPED` 3건**이다.

사전 추정은 54초였는데 실측은 그 2/3 다. 건너뛴 명령이 탭·단언 위주라
파일 평균(2.59초/스텝, 긴 `extendedWaitUntil` 이 섞인 값)보다 싸기 때문이다.
→ 다른 파일에 붙일 때도 **스텝당 평균으로 환산한 추정은 부풀어 있다**고 보는 게 맞다.

⚠️ **건너뛴 케이스는 체크리스트에 SKIP 으로 남는다 — Pass 가 아니다.** 사람이 따로 봐야 한다.
