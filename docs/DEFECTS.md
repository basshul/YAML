## 🐞 D-2026-10-29-01 — 현지어 성명 행의 한국어 라벨이 "성명 (한국어)" 다

**상태:** ClickUp 미보고 · 중요도 Minor(문구) — 다만 사용자가 **조회 결과를 오해할 수 있다**

### 무엇이 잘못됐나
해외송금 수취인 추가 → 제출하면 뜨는 **계좌 확인 다이얼로그**("수취인의 은행 계좌번호 정보를
확인해 주세요.")에는 은행 조회로 받아 온 **현지어(키릴) 예금주명**이 한 줄 들어간다.
그 행의 라벨이 한국어 UI 에서만 **"성명 (한국어)"** 로 나온다. 실제로 그 아래 찍히는 값은
**몽골어 키릴** 이다.

| UI | 라벨 | 그 아래 표시되는 값 |
|---|---|---|
| 한국어 | **성명 (한국어)** ❌ | ЗАГД АНХБАЯР |
| 몽골어 | Крилл овог нэр ✅ | ЗАГД АНХБАЯР |
| 영어(리소스값, 화면 미실측) | Full Name In Your Language ✅ | — |

같은 흐름의 **바로 앞 입력 폼**은 한국어로도 "**현지** 성 (Native Last Name) (선택)" 이라고
제대로 부른다. 즉 한 화면 흐름 안에서 같은 개념을 "현지" 와 "한국어" 로 엇갈리게 부른다.

### 재현
1. 한국어 UI / 해외송금 → 수취인 추가하기
2. 국가 **MONGOLIA** → 수취 방법 **계좌 입금** → 은행 **KHAN BANK** → 계좌번호 **5059080618**
3. 이름 `ANKHBAYAR` / 성 `ZAGD`, 나머지 필수값 채우고 **제출**
4. 계좌 확인 다이얼로그의 두 번째 행을 본다

※ 자동화로 재현: `02_01_해외송금_수취인관리_old.yaml` `[05]`
(`.\run_test.ps1 -lang ko -User <이름> -flow "Old\02_01_해외송금_수취인관리_old.yaml"`)

### 증적
- 한국어 — `Maestro\shots_runs\20261029_103731__tmp_02_01_몽골수취인_old\[05]_몽골수취인_계좌확인.png`
- 몽골어 — `Maestro\shots_runs\20261029_105427__tmp_02_01_몽골수취인_old\[05]_몽골수취인_계좌확인.png`
- 뷰계층 — `Maestro\shots_runs\20261029_103155__tmp_02_01_몽골수취인_old\_maestro\step-100-*.json`
  (`localnametitle` = "성명 (한국어)" / `localnameTxt` = "ЗАГД АНХБАЯР")

### 원인으로 보이는 것 — 문자열 리소스
`full_name_local_text` 의 **ko 값만** 계열에서 혼자 어긋나 있다. 형제들은 전부 "(모국어)" 다:

| 리소스 | ko | en |
|---|---|---|
| `first_name_local_text` | 이름 (모국어) | First Name In Your Language |
| `last_name_local_text` | 성 (모국어) | Last Name In Your Language |
| `middle_name_local_text` | 중간 이름 (모국어) | Middle Name In Your Language |
| **`full_name_local_text`** | **성명 (한국어)** ❌ | Full Name In Your Language |

앱 전체에서 ko 값에 "한국어" 가 들어간 문자열은 **3건뿐**이고, 나머지 2건(`ko`,
`korean_language_text`)은 언어 이름 자체라 정상이다 → **오염 범위는 이 한 줄이다.**

### ★ 이웃 행 중복 — 어느 줄을 고쳐야 하는지
**몽골어 값이 글자까지 같은 리소스가 셋**이다. 몽골어만 보고 지시하면 엉뚱한 줄을 고친다:

| 리소스 | mn (전부 동일) | ko | 판정 |
|---|---|---|---|
| **`full_name_local_text`** | Крилл овог нэр | **성명 (한국어)** | ❌ **이 줄이 화면에 뜬 것** |
| `local_full_name_text` | Крилл овог нэр | 전체 이름(현지어) | ✅ 건드리지 말 것 |
| `receiver_local_name_text` | Крилл овог нэр | 수취인 이름(현지어) | ✅ 건드리지 말 것 |

**식별 근거는 ko 실측값이다** — 화면에 뜬 "성명 (한국어)" 는 셋 중 `full_name_local_text` 에만 있다.

### 권고
`full_name_local_text` 의 **ko 값만** 바꾼다. 형제와 맞추면 **"성명 (모국어)"**,
다이얼로그 문맥을 살리면 "성명 (현지어)". 나머지 두 리소스와 en·mn 값은 **그대로 둔다.**

⚠️ 앱은 Lokalise OTA 라 **APK 값과 화면 값이 다를 수 있다.** 이 건은 APK ko 값과 화면이
일치해 OTA 덮어쓰기가 없는 것으로 보이지만, 수정은 **Lokalise 쪽에서** 해야 한다.

## 🐞 D-2026-10-29-02 — 읽기 전용 확인 행에 입력 지시문 라벨("계좌번호 입력")

**상태:** ClickUp 미보고 · 중요도 Trivial(문구)

위 **같은 다이얼로그**의 계좌번호 행 라벨이 한국어에서 **"계좌번호 입력"** 이다.
이 다이얼로그는 입력란이 아니라 **조회 결과를 확인만 하는 화면**이라 "입력" 이 어색하다.
몽골어는 "Дансны дугаар"(계좌번호), 영어 리소스도 "Account Number" 로 **둘 다 정상**이다.

리소스는 `account_number_text`(ko=`계좌번호 입력` / en=`Account Number` / mn=`Дансны дугаар`).
입력 폼용 라벨을 확인 화면에 **재사용**한 것으로 보인다.

### ★ 이웃 행 중복
`Дансны дугаар` 를 mn 으로 갖는 리소스가 여럿이고, 그중 ko 가 이미 "계좌번호" 인 것들이 있다:

| 리소스 | ko | en |
|---|---|---|
| **`account_number_text`** | **계좌번호 입력** | Account Number |
| `account_no` | 계좌번호 | Account No. |
| `TS_4062_account_no_label` | 계좌번호 | Account No |
| `account_title_text` | 계좌 | Account |

→ 문자열을 고치는 대신 **확인 다이얼로그가 `account_no` 를 쓰도록 바꾸는 쪽**이 안전하다.
`account_number_text` 의 ko 를 "계좌번호" 로 바꾸면 **실제 입력 폼 쪽 문구가 같이 바뀐다.**

증적은 D-2026-10-29-01 과 같은 스크린샷이다.
