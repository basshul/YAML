## 1. 사전 조건 (Pre-condition) — 코드가 아니라 환경에서 갖춰야 하는 것

### 1.1 기기
- **실기기 필수.** 에뮬레이터 불가(생체인증·실계좌 연동).
- 기기 **생체인증은 OFF**로 둔다. 켜져 있으면 지문 화면이 끼어들어 플로우가 갈라진다.
- 해상도가 바뀌면 **좌표 탭을 재보정**해야 한다. 구 UI는 native라 대부분 id로 되어 있지만,
  접근성 트리에 안 잡히는 WebView 텍스트 등 좌표가 남은 곳이 있다.
- **시리얼을 코드에 박지 말 것** — 러너가 `adb devices`로 자동 감지한다. 기기는 교체된다.
- **실행 중 기기를 만지지 말 것.** 알림 패널을 내리면 `Element not found`로 실패해
  셀렉터 버그처럼 오진하게 된다(실제 오진 이력).

### 1.2 계정
플로우가 전제하는 계정이 **5개**다. 다른 환경으로 옮기면 전부 새로 만들거나 값을 바꿔야 한다.

| 계정 | 성격 | 쓰는 파일 |
|---|---|---|
| `seungsoo818` | 한국인·은행 연결됨. **기본 계정** | 대부분 |
| `test123` | 외국인·은행 미연결 | `14_02`, `25_Profile_Foreign`, `_switch_test123` |
| `test251024` | 외국인·GMEPay 신청완료 | `14_03` |
| `test006` / `test007` | **회원가입이 생성하는 계정** | `06_Registration_*` |

- ⚠️ `15_Loan [01]`은 `seungsoo818`이 **한국인일 때만** 통과한다. 국적을 바꾸면 결과가 뒤집힌다.
- ⚠️ `06_Registration_*`은 **멱등하지 않다.** 성공 1회당 ID·이메일·신분증번호·휴대폰번호가
  서버에서 소모된다 → **재실행 전 `test006`/`test007`을 admin에서 삭제**하거나 §3의 값을 전부 새로 바꾼다.

- ⚠️ 계정 전환은 **기존 PIN을 해지**한다 → 로그인 직후 PIN 재등록 분기가 필요하다.
  중간에 끊기면 PIN 없는 상태로 남아 **다음 실행 진입 자체가 막힌다.**

### 1.3 잔액 (GME Wallet)
앱은 **PIN 입력 전까지 잔액을 검증하지 않는다.** 잔액이 부족해도 PIN 화면까지 진행되고,
의도된 PIN 오입력이 **실제로 소모된다.** 그래서 실행 전 잔액 확인이 필수다.

| 플로우 | 필요 잔액(기준) |
|---|---|
| `02_01 [02]` | 14,000원 |
| `16_ATMWithdraw` | 13,000원 |
| `03_Domestic`, `08_MyQR` | 소액(1,000~2,000원 권장) |

⚠️ 잔액 부족은 **FAIL로 위장된다.** 2026-08-28에 `03_Domestic`이 그 사례였다 — 코드는 멀쩡했고
잔액만 부족했다. 스위트는 시작 시 1회 확인 후 **SKIP으로 리포트**하는 방향으로 설계 중이다.

### 1.4 갤러리 픽스처
신분증/ARC/여권 업로드·QR 스캔 케이스는 **`icon_thumbnail`의 index**에 의존한다
("테스트 이미지 4장이 갤러리 최신 4개"라는 전제). 다른 이미지가 쌓이면
앱이 **"OCR이 유효하지 않습니다"** 로 거부한다 — **앱 버그가 아니다.**

→ 해당 플로우 **실행 직전** `.\push_test_images.ps1`. 대상: `25_Profile`, `25_Profile_Foreign`,
`08_MyQR`, `06_Registration_*`.

### 1.5 세션
**하루가 지나면 만료된다.** 진입부터 실패하면 이걸 먼저 의심하고
`01_01_Login_First_old.yaml`로 재로그인한다(**PIN만으로는 복구되지 않는다**).
⚠️ 만료 다이얼로그를 닫고 진행하지 말 것 — 구 UI는 PIN으로 복구되지 않아 의미가 없다.

## 2. JSON / 설정 파일에서 고치는 것

### 2.1 `env\ko.env` · `env\en.env` — 화면 문구 (키 **138개**, 양쪽 동일)
UI 라벨을 `${VAR}`로 참조하는 사전이다. **빌드가 올라가 문구가 바뀌면 여기부터 본다.**

- 형식은 `KEY=값` (JSON 아님). 값에 `|`가 들어가면 러너가 인용 처리하므로 그대로 두면 된다.
- ⚠️ **양쪽 키 집합이 같아야 한다.** 한쪽에만 있으면 `-lang en` 실행에서 `${VAR}`가
  치환되지 않은 리터럴로 남아 **조용히 SKIP**된다. `lint_flows.ps1`의 `E04`가 이걸 잡는다.
- ⚠️ **로그에는 치환 전 원문이 찍힌다** → 실제 치환 여부는 화면 동작으로 확인해야 한다.

### 2.2 `lint_labels.json` — 실측 라벨 사전 (정적 검사기 설정)
빌드가 올라가면 문구·id가 조용히 바뀐다(7.20.0에서 하루 4건). **여기 한 곳만 고치면**
전 파일에 대해 검사가 갱신된다.

| 키 | 내용 |
|---|---|
| `wrongLabels` | "쓰면 안 되는 문구 → 실측 문구". `level`로 ERROR/WARN 지정 |
| `wrongTapLabels` | `tapOn`일 때만 문제가 되는 라벨 |
| `v3OnlySelectors` | 개편 UI 전용 셀렉터(구 UI 파일에 있으면 죽은 코드) |
| `genericLabels` | 범용 탭 금지 라벨(`닫기` 등) |
| `captureBlockedMarkers` | FLAG_SECURE 화면 마커(스크린샷 금지 구간 판정) |
| `accountListMarkers` | 연동 계좌 목록 id(`rvKftcList`) — §4 참고 |
| `injectedEnvVars` | 러너가 주입하는 변수(`APP_ID` 등). 미정의 판정에서 제외 |

⛔ **추측으로 추가하지 말 것.** 실기기 덤프로 확인한 값만 넣는다. 틀린 사전은 오탐을 만들고,
오탐이 쌓이면 검사기를 무시하게 된다.

### 2.3 `lint_whitelist.txt` — 검사 예외
형식 `RULE 파일명:줄` 또는 `RULE 파일명`. **"확인해서 의도된 것임을 확정한 것"만** 넣는다.
넣을 때 왜 안전한지 한 줄 주석을 반드시 붙인다.

### 2.4 `..\Checklist\_bb_mapping.json` — yaml 케이스 ↔ 체크리스트 행 매핑
`write_bb.py`가 결과를 xlsx에 기입할 때 쓴다.
- ⚠️ **결과 열은 라운드마다 이동한다.** 열을 고정하지 말고 헤더(9·10행)를 읽어 확인한다.
- ⛔ **openpyxl로 저장 금지**(스레드댓글·customXml·조건부서식 24파트 파괴 실측).
- ⛔ **Excel COM도 쓰지 말 것** — 동기화 폴더 파일은 ReadOnly로 열려 저장이 조용히 무시된다.
- ⚠️ **검증하지 않은 행은 비워둔다.** 통과로 적으면 과대 보고다.

### 2.5 `flows_index.json` — ⚠️ 낡았다
2026-06-25 생성, 37개 플로우, **개편 UI(루트) 파일 기준**이다. 구 UI 트랙과 맞지 않는다.
쓰기 전에 재생성하거나 무시할 것.

### 3.10 자격정보 (PIN·로그인 비밀번호)
값은 이 문서에 적지 않는다. **별도 보관처가 정본**이다.
- PIN은 다수 플로우에 숫자 탭으로 흩어져 있고, 로그인 비밀번호는 보안 키보드 탭 시퀀스로 들어간다
  → **일괄 치환이 어렵다.** 바뀌면 시간이 걸린다는 것을 예상할 것.
- ✅ **평문 자격정보는 전부 제거됐다**(2026-09-01). 38개 파일 226건을 라벨로 치환했다:
  `<정상 비밀번호>` / `<대체 비밀번호>` / `<구 비밀번호(폐기)>` / `<의도적 오답 비밀번호>` /
  `<정상 PIN>` / `<대체 PIN>`. 실제 값은 별도 보관처에만 있다.
  ⚠️ 값 자체는 여전히 **보안 키보드 탭 시퀀스와 `${PW_CUR_LAST}` 같은 env 변수**로 코드에 살아 있다
  (그건 동작에 필요하다). 없어진 건 **주석·note의 평문 노출**이다.
- 새로 생기지 않게 하려면 `.\lint_flows.ps1`(`W04`)로 확인한다. **한계 두 가지**:
  "비밀번호/PIN" 단어가 같은 줄에 없으면 못 잡고, 특수문자 집합에서 `*`·`^`를 뺐다
  (주석의 마크다운 강조 `**SKIP**`가 오탐이 나서) → `*`로 끝나는 값은 못 잡는다.

  ⚠️ 이 목록은 **"비밀번호/PIN"이라는 단어가 같은 줄에 있는 경우**만 잡은 것이다.
  `# 실패 시 <값> 재시도` 처럼 단어 없이 값만 적힌 주석은 안 잡힌다 → 손으로도 한 번 훑을 것.

## 4. 하드코딩을 고칠 때의 원칙 (2026-09-01 확립)

> **동적 선택은 "무엇을 고르든 케이스가 성립하는" 경우에만.**
> 특정 데이터가 케이스의 일부라면 하드코딩이 맞고, 대신 **그 데이터의 존재를 먼저 단언**한다.

| 상황 | 처방 | 적용 예 |
|---|---|---|
| 어느 값이든 무관 | **목록에서 골라 그 값으로 검증** | `14_01 [25]` 자동이체 계좌 선택 |
| 특정 값이 케이스의 일부 | **하드코딩 유지 + 전제 단언 추가** | `08_MyQR` 실송금 조합(카카오뱅크) |
| 실송금·실결제 | ⛔ **동적 선택 금지** — 어느 계좌로 돈이 갔는지가 재현 가능해야 한다 | `02_01`, `03_Domestic`, `08_MyQR [05][06]` |

### 동적 선택 패턴 (검증됨)
```yaml
- assertVisible:
    id: "rvKftcList"
- assertVisible:                       # ① 선택 가능한 항목이 최소 1개 있는지 먼저 단언
    text: ".*(은행|뱅크)"                #    (없으면 빈 목록에서 조용히 통과한다)
    index: 0
- copyTextFrom:                        # ② 고른 값을 기억
    text: ".*(은행|뱅크)"
    index: 0
- evalScript: ${output.kftcBank = maestro.copiedText}
- tapOn:
    text: ".*(은행|뱅크)"
    index: 0
- waitForAnimationToEnd
- assertVisible: ".*${output.kftcBank}.*"   # ③ 고른 값으로 검증
```
`.*(은행|뱅크)`가 안전한 이유: **Maestro 텍스트는 전체매칭**이라 은행/뱅크로 **끝나는** 문자열만
잡는다 → `GME Wallet`(원복 대상)과 `은행 계좌 선택` 같은 헤더는 매칭되지 않는다.

### 전제 단언 패턴
```yaml
- assertVisible: "신한은행"    # 이 줄이 없으면 목록이 바뀌었을 때 아래 tapOn이
- tapOn: "신한은행"            # Element not found로 죽어 셀렉터 버그처럼 오진하게 된다
```

`lint_flows.ps1`의 **`W10_ACCT_HARDCODED`** 가 "전제 단언 없는 계좌 탭"을 잡는다.

## 6. 알려진 함정 요약 (전체는 CLAUDE.md)

- **텍스트는 전체매칭이다.** 부분 문구를 쓰면 **에러 없이 조용히 SKIP**된다 — 가장 자주,
  가장 늦게 터지는 함정. 가능하면 `id`로 판정한다.
- **id에 패키지명을 박지 말 것** — stag 빌드에서 절대 매칭되지 않는데 조건부 블록이라 SKIP된다.
- **조건부 처리만 있고 assert가 없으면 거짓 통과**가 된다. `extendedWaitUntil`로 결과 도달을
  먼저 강제한 뒤 갈래를 처리한다.
- **`assertNotVisible`은 오타·오역이 있어도 통과한다.** 같은 화면에서 `assertVisible`로 실제
  라벨을 한 번은 확인할 것.
- **PIN 키패드는 탭마다 재배치**된다 → 탭 사이 `waitForAnimationToEnd`(오입력 누적 = 계정 잠금).
- **`inputText`는 한글을 입력하지 못한다** → 검색어는 ASCII 부분문자열을 쓴다.
- **yaml 편집에 PowerShell `Get-Content`/`Set-Content`를 쓰지 말 것** — 파일 전체가 깨진다.
- **개행을 "CRLF"로 단정하지 말 것.** 파일마다 다르다(2026-09-15 전수 실측:
  `Maestro\` 114개 중 **LF 86 / CRLF 25 / 한 파일 안에 섞인 것 3** —
  `13_01_Rate_Indonesia` · `13_04_Request` · `13_05_ExistingSender`).
  `env\ko.env`는 LF인데 `en.env`는 CRLF다. BOM도 `Old\`엔 없지만 루트 개편 UI 사본 2개
  (`04_01_Change_SimplePassword` · `04_06_Settings_Change languages`)에는 있다.
  → 스크립트로 다시 쓸 때는 **읽은 바이트 그대로 보존**하고(`newline=""`로 읽고 감지한 개행으로 join),
  쓴 뒤 `\r\n` 개수를 원본과 대조해 검산한다. 일괄 변환하면 내용은 그대로인데 **전 줄이 변경으로 잡히고**,
  `.gitattributes`가 `* -text`라 저장소에도 그대로 올라간다.
